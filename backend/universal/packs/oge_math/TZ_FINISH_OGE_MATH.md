# ТЗ: добить ОГЭ математику до «готово»

**Проект:** ege_tracker  
**Пак:** `backend/universal/packs/oge_math/`  
**Экзамен:** ОГЭ · Математика · КИМ 1–25 (ФИПИ / демо 2025–2026)  
**Цель:** после выполнения этого ТЗ вариант собирается стабильно, с правильными типами номеров, читаемой вёрсткой и чертежами там, где они нужны в реальном КИМ.

Ответ нейросети/исполнителя — **только данные (JSON + SVG)**, без эссе. Код интеграции делает команда ege_tracker.

---

## 0. Критерий «готово» (приёмка)

Вариант считается закрытым по ОГЭ math, если:

1. **25 заданий** в правильном порядке (1–19 ч.1, 20–25 ч.2).
2. Номера **соответствуют спецификации** (не «похожая математика»).
3. На каждый номер ≥ **4 подтипа** (где номер «ветвистый» — 1–5, 10, 11, 15–19, 20–25 — лучше **6+**).
4. Блок **1–5** — всегда из **одного** `context_block` (общий текст/план/таблица).
5. У блоков с планом — **читаемый чертёж** (сетка, легенда клетки, подписи номеров объектов).
6. У **7, 11, 13, 18** — корректные чертежи/схемы под тип.
7. У **20–22** — **без** декоративных картинок.
8. У **23–25** — эталонный чертёж к решению (SVG) **на каждый подтип**.
9. Дроби/корни в тексте и ответах — школьный вид (`[[a|b]]`, √ с чертой), не «лестница» символов.
10. Ответы ч.1 однозначны; для дробей допустимы `0,5` и `0.5`.
11. 10 подряд сборок варианта **без 500** и без пустых карточек 1–5 / 23–25 (когда у подтипа должен быть рисунок).

## 2. Блок 1–5 — context_blocks (P0)

### 2.1. Сколько нужно
Минимум **8 целостных блоков** (сейчас 3). Цель — **12**.

Обязательные темы (по открытому банку / демо):
1. План дачного участка (уже есть — улучшить)  
2. План квартиры (уже есть — улучшить)  
3. Шины / маркировка (уже есть — без плана, таблицы в тексте)  
4. Печи для бани (таблица характеристик)  
5. Тарифы / интернет / сотовая связь  
6. Зонты / товары (выбор покупки)  
7. Линолеум / плитка / ремонт (площади)  
8. Автомобиль / расход топлива / поездки  
9. *(опционально)* теплица / грядки  
10. *(опционально)* кредит / вклады (простая таблица)  
11–12. ещё 1–2 из реальных КИМ  

### 2.2. Правила блока
- Ровно **5 заданий**: `task_number` 1…5.  
- Общий `description_text` + при необходимости **один** чертёж/таблица на все пять.  
- Ответы согласованы с **одним** набором данных (не разные планы в №1 и №3).  
- Если есть план → `figure_kind: "plan"` + `figure_params.rooms` (целые клетки).  
- Если только таблица → `figure_kind: null`, все числа в тексте.

### 2.3. JSON одного блока
Файл: `context_blocks/<context_id>.json`

```json
{
  "context_id": "stove_bath_01",
  "title": "Печи для бани",
  "description_text": "Общий вводный текст…",
  "figure_kind": null,
  "figure_params": null,
  "tasks": [
    {
      "task_number": 1,
      "part": 1,
      "prototype_title": "Печи для бани · сопоставление",
      "prompt_instruction": "Тип ОГЭ №1: сопоставление по таблице/описанию. Менять только числа/подписи, тип сохранить.",
      "template_text": "Полный текст задания 1…",
      "template_answer": "231",
      "template_solution": null,
      "difficulty": "easy",
      "answer_type": "string",
      "max_score": 1,
      "acceptable_answers": ["231"]
    }
  ]
}
```

Для плана — `figure_params`:

```json
{
  "title": "план участка",
  "width": 12,
  "height": 10,
  "cell_meters": 2,
  "gate": { "side": "bottom", "at": 5, "width": 2 },
  "rooms": [
    { "id": "1", "label": "1", "name": "Дом", "x": 3, "y": 1, "w": 4, "h": 3 },
    { "id": "2", "label": "2", "name": "Баня", "x": 1, "y": 6, "w": 2, "h": 2 }
  ]
}
```

`x,y,w,h` — **целые клетки**; подписи номеров на плане совпадают с ответом-последовательностью.

### 2.4. Сдать
Папку JSON-файлов **или** один массив блоков. Без дублей `context_id`.

## 3. Задания 6–19 — добор подтипов (P1)

Для каждого номера проверить/добавить подтипы в формате прототипа (как в каталоге).

| № | Минимум подтипов | Обязательные виды | Чертёж |
|---|----------------:|-------------------|--------|
| 6 | 4 | обыкновенные / десятичные / смешанные | нет |
| 7 | 4 | корни на прямой / дроби / знаки a,b | numberline |
| 8 | 4 | степени / корни / ФСУ | нет |
| 9 | 4 | линейные / квадратные / рациональные | нет |
| 10 | 5 | классика / брак / жребий / составные | нет |
| 11 | 4 | парабола / гипербола / прямая (с **вариантами 1–3** и ответом-последовательностью) | graph_* + текст вариантов |
| 12 | 4 | линейные формулы / выражение неизвестной | нет |
| 13 | 4 | линейные / квадратные / системы | numberline (решение) |
| 14 | 4 | арифм. / геом. / прикладные | нет |
| 15 | 5 | углы / медиана / тригонометрия | simple triangle optional |
| 16 | 4 | центр/вписанный / касательная / вписанный четырёхуг. | circle optional |
| 17 | 4 | трапеция / ромб / треугольник | rect/triangle optional |
| 18 | 4 | tg / средняя линия / расстояние | **grid** с координатами |
| 19 | 3 | верные / неверные утверждения | нет |

Формат элемента (массив в ответ):

```json
{
  "task_number": 10,
  "part": 1,
  "subtype_code": "10d",
  "prototype_title": "10d: …",
  "prompt_instruction": "…",
  "template_text": "…",
  "template_answer": "0.25",
  "template_solution": null,
  "difficulty": "medium",
  "figure_kind": null,
  "figure_params": null,
  "answer_type": "number",
  "max_score": 1,
  "acceptable_answers": ["0.25", "0,25"]
}
```

Формулы только так: `3x²−4x`, `√(12·3·2⁴)`, `[[x|3]]+[[x|12]]`.  
**Запрещено:** сырой LaTeX `\begin`, `$...$`, слеш-дроби `x/3` в эталонах.

## 4. Часть 2 (20–25) — тексты + чертежи (P0 для 23–25)

### 4.1. Тексты
На каждый номер ≥ **4 подтипа** с `template_text`, `template_answer`, `template_solution` (разбор обязателен).

| № | Тема | figure |
|---|------|--------|
| 20 | уравнения / системы / дроби | **null** |
| 21 | текстовые (движение / работа / смеси) | **null** |
| 22 | график + параметр | обычно **null** (ученик строит сам) |
| 23 | планиметрия вычисление | **SVG обязателен** |
| 24 | доказательство | **SVG обязателен** |
| 25 | сложная планиметрия | **SVG обязателен** |

### 4.2. Чертежи 23–25
См. также `TZ_PART2_FIGURES.md`. Кратко:

- Стиль ФИПИ: чёрное на белом, 2D, буквы вершин, без 3D.  
- Файл: `assets/figures/part2/q{N}_{subtype}_main.svg`  
- В JSON задачи:

```json
{
  "task_number": 23,
  "subtype_code": "23b",
  "figure_kind": "asset",
  "figure_data": {
    "has_condition_figure": true,
    "has_solution_figure": true,
    "figure_type": "svg_file",
    "main_figure_url": "/packs/oge_math/assets/figures/part2/q23_23b_main.svg",
    "steps": []
  },
  "figure_svg_raw": null
}
```

Либо вложить SVG в `figure_svg_raw` (класс `geo-fig fipi-fig`, `viewBox`, без `<script>`).

**Минимум ассетов:** по **4 SVG на каждый** из номеров 23, 24, 25 (итого ≥ 12), плюс тексты подтипов.

## 5. Ответы и проверка

- Ч.1: `answer_type` = `number` | `string` | `sequence` (для «231» / «123»).  
- `acceptable_answers` — все допустимые записи.  
- Ч.2: в `template_answer` — краткий итог; полный ход — в `template_solution`.  
- Критерии баллов (1/2) — желательно короткий `criteria_rubric` в solution (можно позже).

## 6. Формат сдачи (что прислать в чат / файлами)

Одним архивом или несколькими сообщениями:

```text
oge_math_finish/
  context_blocks/     # новые + улучшенные
  subtypes_part1.json # массив прототипов 6–19 (добавки)
  subtypes_part2.json # массив 20–25
  assets/figures/part2/*.svg
  MANIFEST.md         # список файлов + kim_year
```

`MANIFEST.md` пример:
```text
kim_year: 2026
context_blocks: 9 new
part1_new_prototypes: 40
part2_new_prototypes: 24
svg_23_25: 12
```

## 7. Чего НЕ делать

- Не просить GPT «сочинить весь КИМ» без типов номеров.  
- Не слать фото без SVG/координат.  
- Не плодить `box3d` и «красивые» 3D.  
- Не менять коды экзамена (`OGE` / `math`).  
- Не дублировать движок — только контент пака.

---

## 8. Порядок работ (для исполнителя)

1. Добить **8–12 context_blocks** (1–5) → сразу заметный эффект.  
2. Добор подтипов **6–19** + правки формул.  
3. Подтипы **20–22** (без картинок).  
4. Подтипы **23–25** + **≥12 SVG**.  
5. Прогон приёмки из §0 (10 генераций подряд).
