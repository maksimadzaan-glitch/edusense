# Техническое задание: Расширение линейки ОГЭ (5 популярных предметов × 5 прототипов)

**Путь:** `backend/universal/packs/TZ_OGE_POPULAR_5x5.md`  
**Проект:** `ege_tracker`  
**Цель:** JSON-паки для 5 ключевых предметов ОГЭ (математика уже эталон отдельно в `oge_math`).

ОГЭ math **не входит** в эту пятёрку — она уже ведётся в `packs/oge_math/`.

---

## 1. Реестр создаваемых пакетов

```text
backend/universal/packs/
├── oge_rus/         # ОГЭ Русский язык (~9–13 линий × 5 ≈ 45–65 задач)
├── oge_info/        # ОГЭ Информатика (15 линий × 5 = 75 задач + файлы)
├── oge_society/     # ОГЭ Обществознание (24 линии × 5 = 120 задач)
├── oge_physics/     # ОГЭ Физика (25 линий × 5 = 125 задач + SVG)
└── oge_bio/         # ОГЭ Биология (26 линий × 5 = 130 задач + схемы)
```

| Папка | subject_code (PG) | exam_code | Слотов КИМ* | Прототипов на слот |
|-------|-------------------|-----------|------------:|-------------------:|
| `oge_rus` | `russian` | `OGE` | 9–13 | 5 |
| `oge_info` | `informatics` | `OGE` | 15 | 5 |
| `oge_society` | `social` | `OGE` | 24 | 5 |
| `oge_physics` | `physics` | `OGE` | 25 | 5 |
| `oge_bio` | `biology` | `OGE` | 26 | 5 |

\*Точное число слотов — по спецификации ФИПИ выбранного года; указать в `pack_info.kim_year` и `slot_count`.

Маппинг учителя уже частично есть в `backend/universal/codes.py` — при импорте сверить коды (`russian`, `informatics`, `social`, `physics`, `biology`).

## 3. Формат JSON (сдача нейросети)

Один файл на предмет, например `imports/oge_rus_v1.json`:

```json
{
  "pack_info": {
    "pack_id": "oge_rus",
    "subject_code": "russian",
    "exam_code": "OGE",
    "kim_year": 2026,
    "slot_count": 9,
    "version": "1.0.0"
  },
  "context_blocks": [],
  "tasks": [
    {
      "id": "oge_rus_q01_001",
      "task_number": 1,
      "part": 1,
      "subtype_index": 1,
      "prototype_title": "1 · …",
      "template_text": "Условие…",
      "template_answer": "…",
      "template_solution": null,
      "difficulty": "easy",
      "answer_type": "string",
      "max_score": 1,
      "acceptable_answers": [],
      "figure_kind": null,
      "figure_params": null,
      "figure_data": null,
      "context_id": null
    }
  ]
}
```

Допустимы алиасы как в math-finish: `statement`→текст, `correct_answer`→ответ (импортёр нормализует).

**Правило 5×N:** на каждый `task_number` ровно **5** задач (`subtype_index` 1…5), разные формулировки одного типа номера ФИПИ.

## 4. Требования по предметам (коротко)

### 4.1. `oge_rus` — Русский
- Линии по актуальному КИМ (сжатое изложение / тесты / сочинение — как в спецификации года).
- Ч.1: однозначный или короткий ответ; ч.2: `answer_type: "detailed"` + критерии в `template_solution` / `criteria_rubric`.
- Картинок почти нет.
- Орфоэпия, нормы, средства выразительности — без выдуманных «не тех» номеров.

### 4.2. `oge_info` — Информатика
- 15 номеров × 5.
- Где нужны файлы (таблицы, строки, исполняемый фрагмент) — класть в `assets/files/` и ссылать из условия текстом/путём.
- Ответы проверяемые (число, строка, последовательность).
- Без «псевдокода, который нельзя однозначно исполнить», если номер требует точного ответа.

### 4.3. `oge_society` — Обществознание
- 24 × 5.
- Выборы номеров, краткие ответы, задания к тексту/графику.
- Ч.2: развёрнутый + краткий эталон и рубрика 0/1/2.

### 4.4. `oge_physics` — Физика
- 25 × 5.
- Единицы СИ в ответах; `acceptable_answers` с вариантами записи.
- SVG/схемы только где в реальном КИМ есть рисунок; стиль как в `oge_math` (чёрное на белом, `geo-fig fipi-fig`).
- Формулы: unicode / `[[a|b]]`, не сырой тяжёлый LaTeX в эталоне UI.

### 4.5. `oge_bio` — Биология
- 26 × 5.
- Схемы/рисунки — SVG или чёткое описание `figure_params`; без бессмысленных декораций.
- Термины по кодификатору; не путать линии номеров.

## 5. Приёмка одного пака

1. `slot_count` задач в варианте при сборке.  
2. На каждый номер ровно 5 прототипов в базе после импорта.  
3. Нет 500 при generate; пустые шаблоны запрещены.  
4. Для info/physics/bio: битых ссылок на assets нет.  
5. Глазами: 2 случайных варианта — типы номеров узнаваемы.

Импорт (когда скрипт будет / по аналогии с math):

```powershell
python -m backend.scripts.import_oge_pack --pack oge_rus
# или временный import_* на каждый предмет
```

## 6. Порядок внедрения в продукт

1. Каркас папок + `pack_info` для пяти паков.  
2. Импортёр JSON → Postgres (`task_prototypes`), маппинг в `codes.py`.  
3. Контент по очереди: **rus → info → society → physics → bio**.  
4. UI: предмет доступен в «Собрать вариант», если есть шаблоны.  
5. После пятёрки ОГЭ → ЕГЭ 5×5 (отдельное ТЗ) → функции продукта.

## 7. Промпт для нейросети (копипаст)

> Сделай пак ОГЭ · {Русский|Информатика|Обществознание|Физика|Биология} на {год} ФИПИ.  
> На **каждый номер КИМ — ровно 5** разных прототипов одного типа задания.  
> Верни один JSON: pack_info + tasks[] (и context_blocks/files/svg_content только если нужно).  
> Поля: task_number, part, template_text, template_answer, template_solution, answer_type, max_score, acceptable_answers, difficulty.  
> Код и архитектуру не пиши.
